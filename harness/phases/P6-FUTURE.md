# P6 — Future (proposals & expansion)

**Purpose:** enhancement, improvement, and expansion — every idea gets the proposal
treatment: drafted, shared with the user, answered on record, then integrated. The
user's request section 5, plus the standing pipeline for growth.

**May run:** any time after G1. It never gates the chain and never displaces launch work
(P5 horizon-0 tasks outrank everything until launch completes).

## The proposal cycle (strict)

```
PIPELINE → DRAFT → REVIEW (orchestrator) → SHARE [U] → RESPONSE → INTEGRATE
```

1. **Capture** — new opportunities land in the pipeline table (`docs/future/00-pipeline.md`):
   expansion (new market/segment/channel), product extension, partnership, automation,
   operational improvement, M&A/investment, moonshot. Include the trigger (metric, insight,
   user idea, pattern).
2. **Draft** → `docs/future/proposal-vN.md` per template: idea, evidence, options, costs,
   benefits, risks, requirements, recommendation, decision needed. Each proposal gets `PROP-n`.
3. **Review** — orchestrator checks: is the evidence real? does it fit goals and capacity?
   small file, honest numbers, worst case. Revise or return to pipeline.
4. **Share [U]** — present to the user with the compact format: options + tradeoffs +
   recommendation + what's needed from them. Never assume acceptance from silence.
5. **Response on record** — the user's answer, **verbatim quote with date**, lands in the
   proposal doc: accepted / declined / deferred (with conditions or trigger date).
6. **Integrate** — accepted: tasks created with owners/dates (respecting horizon rules),
   plans amended via supersede convention, decisions logged; declined: stays on record with
   the reasoning (cheap to revisit, impossible to re-litigate from memory); deferred: trigger
   + date in the pipeline; re-surface at the next quarterly review.

## Cadence

- **Proposal aging (decision debt rules):** a proposal **shared but unanswered** is flagged
  at the monthly snapshot after 30 days; **auto-deferred at 60 days** with a re-surface
  trigger at the next quarterly review (trigger + date recorded in the pipeline row).
  Unanswered proposals are decision debt — they age, they don't linger silently.
- **Quarterly review slot:** rank the pipeline, pick at most 1–3 proposals to draft (capacity
  honesty), retire the dead ones. The pipeline is a funnel, not a museum.
- Any metric that crosses its `watch-level` (quarterly gate) can force a proposal early.
- Post-launch new idea? Pipeline first, always. The register protects the launch.

## Done when (per proposal)

Draft exists, shared, answered on record, integrated or retired. The pipeline stays honest:
ranked, dated, no zombies.

## Failure modes

- Integrating without a recorded response ("they seemed keen") — that's how scope creeps into launch.
- Proposal sprawl: five half-drafted proposals beat zero executed ones, but ten executed
  beats all of it — capacity honesty.
- Research-free proposals — even moonshots need an evidence section (or an explicit label:
  "faith-based, kill-test pending").
- Silent pipeline rot — a proposal that never got shared is a failure at step 4.

## Gate criteria

None — P6 is governed by the quarterly gate and the proposal cycle itself.
