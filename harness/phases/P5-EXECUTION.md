# P5 — Execution Plan

**Purpose:** convert everything into a dated, owned, calendared task list across horizons,
then enter launch mode. The user's request section 4: execution plan, task list, calendared
events, and the new-company metadata tagging that keeps obligations findable.

**Starts when:** G3 and G4 both recorded. **Exits at:** G5 → **LAUNCH MODE**. **Span:** ~1 week.

## Steps

1. **Harvest every promise** — sweep P2–P4 docs and gates for anything that must happen:
   filings, purchases, hires, builds, launches, reviews. Every harvest becomes a `T-P5-nnn`
   row (or lands in an earlier phase's ID range with a note). **Nothing promised lives
   outside `registers/tasks.md`.**
2. **» Horizon sort** (per CONVENTIONS.md):
   - **Horizon 0 (now, ≤30 days):** launch path — legal filings, banking, first GTM moves,
     first customer actions, first build.
   - **Horizon 1 (≤90 days):** operating rhythm — bookkeeping live, first campaigns,
     early metrics, first review cycles.
   - **Horizon 2 (≤1 year):** growth & maturation — hires, expansion, certifications,
     partnerships, the P6 shortlist seeds.
3. **» Dates, owners, done-when** for every row. Owners: founder / orchestrator / specialist /
   professional. Done-when = checkable evidence.
4. **» Critical path** — the ≤7 tasks that, if late, move launch. Named at the top of the
   execution plan; reviewed with the user.
5. **» Calendar sync** — every dated task becomes `[SLUG] <text>` on the user's calendar
   (agent tooling) — created at this step, not "later". Legal/financial deadlines get
   1440-min reminders. Recurring: weekly review, monthly snapshot, quarterly review, and
   any compliance renewals. Where calendar tooling is absent, the register is the record.
6. **» Launch checklist** → `docs/plan/50-execution-plan.md` (template): the ordered
   "first 30 days" list — pre-launch gates (legal done, finances ready, stack live),
   launch-day actions, post-launch first week. **[U]** user approves before launch mode.
7. `validate` → **G5 [U]** → **ENTER LAUNCH MODE**: work horizon-0 tasks until launch-day
   actions are done → announce launch → first weekly review scheduled.

## Launch mode rules

- Work tasks top-down by horizon and date; nothing in H1/H2 displaces H0 until launch completes.
- New ideas during launch → capture as P6 proposal drafts or question rows, never as new
  horizon-0 scope (that's how launches slip).
- After launch-day actions complete, P7 operating rhythm takes over.

## Done when

All tasks dated/owned with done-when; critical path named and user-reviewed; calendar
events created and tagged; launch checklist approved; G5 recorded; launch mode running.

## Failure modes

- Dates set from optimism — dates come from lead times and working sessions, not hopes.
- Orphan TODOs in doc prose that never made it into the register (the harvest step exists for this).
- Calendar never synced (the most common silent failure — the user finds out when a deadline bites).
- Launch checklist treated as a formality — it's the [U] gate before real money moves.
- Horizon inflation: everything is not horizon 0; sort ruthlessly.

## Gate criteria (G5)

Tasks complete with owners/dates; horizons cover all P2–P4 outputs; every gate condition has
a task; calendar tagged and synced; critical path reviewed **[U]**; launch checklist approved **[U]**.
