# P3 — Business Plan

**Purpose:** write the master operating document — how the business operates, its objectives,
how the plan gets *followed*, with the localized and personalized details that make it real.
A stranger should be able to execute this business from the paper.

**Starts when:** G2 (P4 may run in parallel for tech-heavy types). **Exits at:** G3. **Span:** 2–4 weeks.

## Steps

1. **Read** `docs/business-plan/00-master-plan.md` (template) fully. Pull the business-type
   playbook for **»/~** routing; stub the ~ sections with a pointer decision, deepen the » ones.
2. **» Master plan sections:** concept, problem/solution, market (link P1 doc, summarize +
   IDs), offering & pricing, revenue model, objectives, ops model (who does what daily/weekly),
   local details (» the localized story: geography, community, personal), team plan, financial
   summary (link P3 financials), risks summary (link risks register).
3. **» `30-competition-analysis.md`** — competitors, positioning, honest edge, pricing context.
   If P1's snapshot suffices per playbook, link it and deepen only what's thin.
4. **» `40-marketing-gtm.md`** — GTM: channels, launch, outreach, content, partnerships, sales
   motion, referral; localized to the region and community. Name the first 10 customers or
   the first 100, concretely.
5. **» `50-brand-identity.md`** — name, voice, visual identity draft, tagline options, domain.
6. **» `20-financial-plan.md`** — projections build from facts + assumptions: 12-month cash,
   3-year P&L sketch (or the lean variant), break-even, unit economics refined from P1,
   worst case. Every driver is an `A-nnn` or `F-nnn`. No orphan numbers.
7. **» Plan-follow mechanics** (the "how to ensure the plan is followed" requirement) — a
   section in the master plan that names the operating cadence (weekly/monthly/quarterly
   rituals from RUNBOOK.md), metric targets, review checkpoints, who reviews, and the
   amendment rule (quarterly gate variance ≥25% → amend). Make adherence checkable.
8. **Localized & personalized details** (» for local/niche types): region specifics (laws,
   geography, market quirks), community connections, founder story and personal constraints,
   named relationships and assets.
9. `validate` → walk the master plan past the user → **G3 [U]** → announce P4/P5.

## Writing rules

- **Reference, never duplicate:** market numbers link `F-nnn`s; risks link `R-nnn`s; assumptions
  link `A-nnn`s. The plan narrates; registers hold data.
- **Estimates visible:** every unverified number `est. + A-nnn`.
- Write for the stranger-executor: no "obviously", no "as discussed".
- Length follows the playbook: a lean plan is a pass, an inflated one is a failure mode.

## Done when

All template sections filled or deliberately stubbed; financial projections tie to facts;
follow-mechanics section exists with dated review checkpoints; user approved; G3 recorded.

## Failure modes

- Plan drifts from evidence — numbers in the plan that contradict registers.
- Generic filler ("leverage synergies") — the localized/personalized test catches this.
- The plan reads like a pitch deck — it's an operating document.
- No follow-mechanics (a plan nobody checks is a wish).
- Perfectionism: this plan is amended quarterly; make it good enough to operate, not to frame.

## Gate criteria (G3)

Localized story complete; assumptions cross-referenced; financials tie to facts;
followability check passes; **[U]** user approves. See GATES.md.
